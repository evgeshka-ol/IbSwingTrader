# Наблюдение за упавшими тикерами и диагностика ReversalHook

Дата: 2026-10-10. Изменения исходного кода; сборку, тесты и запуск приложения
выполняет пользователь.

## Постоянный виш-лист

В `get-candidates` восстановлено чтение и сохранение `Data/Tickers/wishlist.csv`.
Из `TOP_OPEN_PERC_LOSE` и `TOP_PERC_LOSE` сохраняются все тикеры, прошедшие
базовый фильтр инструмента. Проверки цены по истории, паттерна и готовности
сделки выполняются позже и не являются условиями включения в наблюдение.
Весь полученный список упавших записывается перед длительными запросами
истории; итоговые статусы записываются после публикационной проверки.
CSV заменяется через временный файл, чтобы прерванная запись не обнулила
предыдущий список.

В начале следующего запуска активные записи дают дополнительную вселенную
тикеров: их история запрашивается напрямую, без требования снова попасть
в какой-либо сканкод. Используется общий процесс подготовки/классификации
BellUp -> ReversalHook -> Other и существующие кеши текущего запуска.
Ошибки истории, отсутствие свежих M5 и статус Other сохраняют запись.
Распознанные тикеры также остаются в наблюдении до истечения срока.

Настройки `GetCandidates`:

```json
"UseWishListFirst": true,
"MaxWishListItems": 0,
"ReversalWatchList": {
  "Enabled": true,
  "RetentionCalendarDays": 30,
  "ScanCodes": ["TOP_OPEN_PERC_LOSE", "TOP_PERC_LOSE"]
}
```

`UseWishListFirst` задаёт порядок подготовки истории, а не немедленную
публикацию до завершения остальных этапов. По умолчанию проверяются все
активные записи. Положительный MaxWishListItems задаёт ограничение на один
запуск: первыми идут давно не проверявшиеся, остальные сохраняются.
Срок жизни отсчитывается от последнего появления в коде падения;
обычный прямой опрос его не продлевает. Значение срока <=0 отключает expiry.
Новый виш-лист начинает накапливаться при следующем запуске приложения;
исторический candidates.csv автоматически не импортируется.

Существующие записи из кодов падения импортируются с их ScanTime как датой
последнего падения, если ещё не истекли. Другие старые строки сохраняются,
но автоматически не включаются в новый процесс наблюдения.

Поля наблюдения: FirstSeen, LastDropSeenAt, WatchCurrency, WatchStockType,
LastEvaluatedAt, LastStatus, LastStatusReason, LastStatusTime.
`LastStatus` отражает группу кандидата, а не исход сделки. Если попытка
не дала опубликованного результата, записывается Watching с явной причиной.
Действующие свечи и признаки остаются в кеше/candidates.csv; старые поля
серий в wishlist не являются самостоятельным источником текущего сигнала.

`IsFromWishlist` теперь отражает присутствие в активном списке на старте
запуска, а не принадлежность старой below-Daily-mid семье.
При совпадении live и watch источника публикуется один тикер;
публикационная проверка выбирает именно контекст сохранённого кандидата
по тикеру, сканкоду и времени наблюдения.

Старая очистка по отсутствию/просрочке ожидаемой цели не применяется к
управляемым строкам наблюдения: сроком управляет ReversalWatchList.
Явная пометка Remove продолжает учитываться. При отключении новой функции
файл не перезаписывается. Больше активных тикеров может увеличить длительность
скана; ограничители пустых исторических чанков и возраста M5 bridge сохранены.

## Дополнительная диагностика

`GetCandidates.Finder.ReversalSupplementalDiagnostics=true` включает
`ReversalSupplemental(DiagnosticOnly=True, ...)` в PatternVerdictReason
и журнальную строку Reversal episode.

- ClosedH4Gradual: исследовательская форма постепенного замедления средней
  совместно с восстановлением цены и гистограммы.
- PartialStatus: InsufficientH4History, NoObservedM5, IncompleteOrStale или Fresh.
- При достаточном покрытии: время начала/решения/последнего наблюдаемого M5,
  числа M5, точные OHLC/объём, Bollinger, MACD, RSI, PartialGradual,
  PartialPhase и PartialBarsSinceBend.

Используются только M5, возвращённые текущему запуску и уже закрывшиеся
к границе запроса. Требуется покрытие начала H4 без внутренних пропусков
и положительный объём; последний наблюдаемый close не старше десяти минут
после окончания его M5. Частичная H4 считается на отдельной копии префикса.
Подтверждённые серии сохраняют только закрытые свечи.

Дополнительных запросов M5 ради диагностики нет: используется существующий
ограниченный bridge, а при публикации — уже выполненный свежий запрос.
Закрытые признаки берутся из кеша запуска; рассчитывается только новая точка
частичной свечи. Ошибка дополнительных расчётов фиксируется в логе и не
изменяет решение основного классификатора.

Диагностика не разрешает вход, не меняет ranking/Win~, не снимает RSI и
сжатие полос из строгого исторического seed. Это следующий этап после
`research-2026-10-10-reversal-recognition.md`: сбор живых наблюдений без
подмены доступных тогда данных позднее дополненным кешем.
