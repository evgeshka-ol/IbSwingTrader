# Автоматический запуск сканера в Windows

Расписание использует **локальные часы Windows**. Для Афин/Софии это обычно
UTC+3 летом и UTC+2 зимой. Скрипты не меняют часовой пояс компьютера и не
переводят выбранное время в ET. Логика биржевого дня внутри приложения
продолжает использовать биржевое время.

## Установка

Пример для 23:15 местного времени (пример, не установленное расписание).
В PowerShell из корня репозитория:

```powershell
.\tools\Register-ScannerSchedule.ps1 -AtLocal '23:15'
```

Можно задать несколько запусков и другой собранный executable:

```powershell
.\tools\Register-ScannerSchedule.ps1 -AtLocal '07:00','23:15' -ExePath 'C:\Git_Home\IbSwingTrader\IbSwingTrader\bin\Debug\net10.0\IbSwingTrader.exe'
```

По умолчанию берётся Debug/net10.0 executable этого репозитория. Рядом с ним
обязателен agentsettings.json: рабочая папка задания — папка executable,
поскольку приложение читает настройки относительно неё. Сборка автоматически
не выполняется. Повтор той же команды обновляет задание
`IbSwingTrader-GetCandidates`; скан немедленно не запускается.

Без регистрации можно посмотреть предполагаемое действие:

```powershell
.\tools\Register-ScannerSchedule.ps1 -AtLocal '23:15' -WhatIf
```

По умолчанию запуск ежедневный: это не теряет пятничный биржевой вечер,
если выбранное местное время уже приходится на субботу. При необходимости
ограничить именно местные дни:

```powershell
.\tools\Register-ScannerSchedule.ps1 -AtLocal '23:15' -DaysOfWeek Monday,Tuesday,Wednesday,Thursday,Friday
```

Биржевые праздники и выходные проверяет существующий get-candidates.
В обычные недели 23:15 в Афинах/Софии — через 15 минут после закрытия
регулярной сессии США; в недели несовпадающих переводов часов — позже
относительно закрытия. Фиксированное местное расписание не гарантирует
фиксированного интервала после закрытия биржи. Вечерний запуск проверяет
все текущие группы, а не только ReversalHook; появление хука не гарантируется.

## Условия работы и результаты

- Пользователь должен оставаться вошедшим в Windows; заблокировать экран
  можно. Пароль не сохраняется, вход в Windows или TWS автоматически не
  выполняется. TWS/IB Gateway должен быть заранее запущен и подключён.
- Компьютер должен быть включён и доступен в момент запуска. Для попытки
  пробуждения из сна добавь `-WakeComputer` при регистрации; требуются
  разрешённые таймеры пробуждения Windows. Это не включит выключенный ПК.
- Пропущенные запуски автоматически позже не догоняются; автоматических
  повторов после отказа TWS нет. Ошибка подключения завершает текущий запуск
  с ненулевым кодом, обычным поведением приложения.
- Одновременные экземпляры одного задания запрещены (`IgnoreNew`). Обёртки
  с общей папкой логов дополнительно защищены файловой блокировкой.
  Если процесс с именем executable уже работает, очередной запуск пропускается.
  Это best-effort проверка ручных запусков: приложение не получило общей
  блокировки, поэтому ручной запуск после проверки всё ещё может совпасть
  с автоматическим. Не запускай вручную параллельные команды приложения.
- Окно автоматического запуска скрыто. В
  `Data\logs\scheduled-scans` сохраняются status/stdout/stderr каждого запуска;
  штатные CSV и журналы приложение пишет по своим настройкам. Ограничение
  длительности задания отключено, чтобы Планировщик не обрывал долгий скан.
- Автоматически запускается только `get-candidates`. Оценка, сборки и
  исследовательские команды не добавлены в расписание.

## Просмотр, отключение, удаление

```powershell
Get-ScheduledTaskInfo -TaskName 'IbSwingTrader-GetCandidates'
Disable-ScheduledTask -TaskName 'IbSwingTrader-GetCandidates'
Enable-ScheduledTask -TaskName 'IbSwingTrader-GetCandidates'
Unregister-ScheduledTask -TaskName 'IbSwingTrader-GetCandidates' -Confirm:$false
```

Эти действия выполняет пользователь на Windows. Codex подготовил исходники,
но не регистрировал задание и не запускал скан. PowerShell/ScheduledTasks
недоступны в текущей Linux-среде; проверка Windows-регистрации и реального
исполнения остаётся за пользователем. Сборки и тесты приложения не запускались.

Механизмы сверены с документацией Microsoft:
[daily/weekly triggers](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasktrigger),
[interactive principal](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtaskprincipal),
[task settings](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasksettingsset).
