# Резерв текущей цены для ReversalHook

2026-10-10. Изменён исходный код; сборки и брокерские проверки выполняет пользователь.

## Причина

ALHC в скане 2026-10-09 07:30:07 распознан на D1, фаза Active.
Перед публикацией в 07:20 запрос свежих M5 дважды получил HMDS no data,
поэтому кандидат стал Other. Это отсутствие ответа исторического сервиса;
доступность текущего потока котировок проверяется отдельным API-запросом.
Не доказано, что конкретно ALHC получил бы такую котировку в тот момент.

## Реализация

На этапе публикации уже распознанного ReversalHook сохраняется приоритет
свежих M5. При пустом/непригодном ответе или исключении M5 выполняется
ограниченный по времени `reqMktData` с live режимом и generic tick 233.
Это короткая streaming подписка, отменяемая в finally, не regulatory snapshot.
Для всех диагностических тикеров новый запрос не выполняется.

1. Подтверждённый `marketDataType=1`, положительные bid/ask,
   ask >= bid, спред не более 2%: цена покупки = ask.
2. Если подходящего полного стакана нет, по завершении ожидания допускается
   цена из RTVolume, где цена сделки и её UNIX timestamp приходят одним
   событием. Возраст сделки не более 60 секунд, будущее время допускается
   только в пределах двух секунд на расхождение часов.
3. Известный текущий широкий/перекрещённый bid/ask не обходится последней сделкой.
4. Delayed/frozen/неподтверждённый режим, неположительные цены и старая
   сделка не принимаются. Ошибки entitlement фиксируются в логе.

Таймаут по умолчанию 8 секунд (настройка, диапазон 1–30). Свежий bid/ask
завершает ожидание раньше. Разрыв соединения завершает ожидание без цены.
Age и spread также настраиваются. После построения плана age резервной
цены проверяется повторно; устаревший резерв не публикуется.

Исходные свечи по-прежнему нужны для распознавания, старшего контекста и
расчёта уровней. Котировка не создаёт M5/H4 и не является seed паттерна.
Фаза, BellUp precedence, поддержка старшего масштаба и структура плана
проверяются обычным способом с полученной ценой. Если они не проходят,
тикер остаётся Other независимо от успешного резервного запроса.

## Происхождение цены

- `IBLiveAskObserved`: PriceTime — момент получения ask, **не биржевое
  время обновления заявки** (top-of-book не даёт его в tickPrice).
- `IBLiveLastTrade`: PriceTime — время сделки из RTVolume.
- Source/PriceTime/ObservedAt записываются в существующие поля TradePlan,
  фазовый PriceSource и лог. M5Previous/M5Current и ReferencePriceBarTime
  для этого резерва пусты; M5-проекция тела не применяется.
- PublicationRefreshStatus=`ReversalLiveQuoteFallback` при допуске.

## Настройки

`GetCandidates.Finder`:

```json
"ReversalLiveQuoteFallback": true,
"ReversalLiveQuoteTimeoutSeconds": 8,
"ReversalLiveQuoteMaxAgeSeconds": 60,
"ReversalLiveQuoteMaxSpreadPct": 2.0
```

Механизм не меняет подписки аккаунта: live-котировка требует соответствующего
доступа в IB. Без него будет явный отказ, без подстановки delayed/frozen.

Семантика API сверена с первичными источниками IB:
[типы данных](https://interactivebrokers.github.io/tws-api/market_data_type.html),
[bid/ask и RTVolume](https://interactivebrokers.github.io/tws-api/tick_types.html).

## Что смотреть в следующем запуске

`Live quote fallback request/result/IB response`, источник/время цены и
`ReversalLiveQuoteFallback` в опубликованном плане. Практическое сокращение
числа отказов ещё не измерено. Сборки, тесты и запросы брокеру Codex не запускал.
